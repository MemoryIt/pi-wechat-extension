## A. 启动与连接（本轮重点：A3）
- [ ] A1 插件被加载：pi 启动 `[Extensions]` 含 `src`
- [ ] A2 自动连接：启动日志出现 `session_start: loaded token for userId=...`（`SessionService.startFromStoredToken`）与 `Single user initialized`
- [ ] **A3（重点）** 重启后连接状态同步：登录认证后退出 pi 再重新打开，**立即**执行 `/wechat status` 应显示
      `Connection: connecting`；首次 getUpdates 返回后刷成 `connected`（不应再停留在 Not Connected / 旧状态）
- [ ] A4 未登录时启动：清空凭证后启动，不应崩溃；`/wechat status` 显示 `Not logged in`

## B. 登录 / 登出 / 持久化（应用层回归）
- [ ] B1 `/wechat login` 显示二维码（终端二维码或可点击链接）
- [ ] B2 微信扫码后登录成功，凭证落盘（`~/.pi/agent/wechat/accounts/{id}/token.json`，chmod 600）；
      登录成功摘要只含脱敏后的 `botToken`（D11）
- [ ] B3 登录后自动开始轮询（`SessionService.login` → `startPollingWith`，无需手动 start）
- [ ] B4 重启 pi 后自动用凭证连接（A2 复验）
- [ ] B5 `/wechat logout` 清除凭证（`accounts/{id}` 下文件被清；`status` 变 Not logged in）
- [ ] B6 登出后再启动不自动连接

## C. 双向文本与 turn 识别（应用层决策回归）
- [ ] C1 微信发普通文本 → pi 终端出现该 user 消息 → AI 回复发回微信（含最终版）
- [ ] **C4（重点回归）** 微信 turn 回复**只发一次**：`agent_settled` 的发送决策在 `ReplyService.handleSettled()`
      （防重命中 `isRequestProcessed` 则跳过；无 `requestId` / 无回复文本早退），无重复/漏发
- [ ] **D1/D2/D5 语义回归**：发送成功才 `markRequestProcessed`（失败轮可重试，D2）；
      所有路径 `finally` 释放队列（D1）；回复只发一次（D5）
- [ ] C5 终端处理中到来的微信消息**排队**，终端轮结束后按序处理
- [ ] C6 微信连发多条：按 FIFO 顺序逐条处理，不丢、不乱序
- [ ] C7 微信发以 `/` 开头：`/help` 有响应；其它 `/xxx` 被引擎拦截（不进入 AI）

## F. 媒体接收（本轮重点：F6）
- [ ] F1 微信发**纯图片**：立即回执「媒体文件已收到，正在保存…」
- [ ] F2 后台下载解密落盘，路径形如 `{mediaStoragePath}/{YYWW}/{YYMMDDHHMMSSmmm}_{uuid8}.{ext}`
- [ ] F3 保存后路径写入会话历史（`wechat_media`，不触发新 AI turn）
- [ ] F4 图文混合消息：按文本 turn 处理（媒体也落盘）
- [ ] F5 语音 / 视频 / 文件：可下载落盘（silk→wav 转码若依赖可用）
- [ ] **F6（重点）** 连发 3 张图片后再发 1 条文本 → 文本应**即时响应**（不被下载中的媒体阻塞）：
      - 日志**无** `Failed to handle message`（单条 onMessage 失败隔离，`polling.ts`）；
      - 日志**无** `Media ack failed` 重投循环（媒体 ack 失败仅记录，`router.ts`）；
      - `sync.json` 的 syncCursor **持续推进**（不因失败消息停滞）
- [ ] F7 多个媒体**串行**落盘，第 2 个等第 1 个完成（B5）
- [ ] F8 单项下载失败：记录错误后继续，不影响其它项

## H. 命令与生命周期（应用层回归）
- [ ] H1 `/wechat status`：`Logged in` + 正确 userId + `Connection: <状态>`（连接状态取自 `SessionChannel.connectionState`）
- [ ] H2 `/wechat stop` 停止轮询（`status` → disconnected），在途请求不再阻塞循环（D9）
- [ ] H3 `/wechat start` 重新启动轮询（`SessionService.start`，有 token 才启动）
- [ ] H4 登录无效时 `/wechat start` 提示「Not logged in. Use /wechat login first.」
- [ ] H5 `/wechat ` 子命令补全：login/status/start/stop/logout（`registerCommands` 委托 `SessionService`）
- [ ] H6 `session_shutdown`（退出 pi）→ `SessionService.shutdown()` 停止轮询、重置状态，不残留
- [ ] H7 再次启动 pi 不重复开轮询、不并发第二条循环（D3）

## I. 故障与边界
- [ ] I1 登录失效（换 contextToken / 会话过期）：连接状态变 `needs_relogin`，UI 提示「微信登录已失效，请执行 /wechat login 重新登录」；该终态不被覆盖（B4）
- [ ] I2 发送失败：UI 报「微信回复失败」（`ReplyService` 捕获 + `notify`）；失败轮**不**标记已处理，可重试（D2）
- [ ] I3 发送成功后才标记 request 已处理；去重命中 early-return 仍释放队列（D1）
- [ ] I4 凭证缺失时 `sendWithRetry` 立即抛错、不重试、不空转
- [ ] I5 日志不出现明文 botToken / context_token（D11 脱敏，含登录成功摘要）

## J. 配置与持久化
- [ ] J1 `WECHAT_DEBUG=true` 或 `config.json {"debug":true}` 时输出 debug 日志
- [ ] J2 环境变量按字段覆盖：只设 `WECHAT_MEDIA_PATH` 不影响 `debug`（D8）
- [ ] J3 `mediaStoragePath`/`WECHAT_MEDIA_PATH` 生效于媒体落盘路径
- [ ] J4 状态目录布局：`~/.pi/agent/wechat/{accounts.json,config.json,accounts/{id}/{token.json,context-tokens.json,sync.json}}`
- [ ] J5 `sync.json` 的 syncCursor 随轮询推进（F6 中一并观察）

## K. 已知限制（确认符合预期，非遗漏）

## 排障
- 看不到日志：开 `WECHAT_DEBUG`；或看 `~/.pi/agent/wechat/` 与 `tools` 输出
- A3 不满足：确认 `PollingLoop.start()` 在首次 getUpdates 前已把 `connectionState` 置为 `connecting`
  （`src/channel/polling.ts`；`tests/channel` 有回归，若人工复现不了可能是时序/日志视角问题，记录现象即可）
- F6 复现：连发图片后立刻发文本，若文本长时间无响应，抓日志看是否出现 `Failed to handle message` /
  `Media ack failed`；两者都应**只出现一次**且不进入重投循环
- 回复失败：看是否 `needs_relogin` → 重新登录
- 媒体没保存：检查 `mediaStoragePath` 可写
